# C# — 落地细则

Source: https://learn.microsoft.com/dotnet/csharp/fundamentals/coding-style/coding-conventions
配套：.editorconfig + Roslyn analyzers（CAxxxx / IDExxxx）+ `dotnet format`；先以仓库 .editorconfig 与 Directory.Build.props 为准。

## 1 适用范围与优先级

- 覆盖手写 C# 源码（`.cs`，含 `.razor`/`.cshtml` 中的 `@code` 块）；生成的代码（`obj/`、`*.Designer.cs`、带 `<auto-generated>` 头的文件）不评审、不格式化。
- 官方文档自称"示例性清单、非权威列表"：它由 dotnet/runtime 与 Roslyn 的 coding style 派生，但不是唯一标准；靠 .editorconfig 落地才有约束力。
- 优先级：仓库 `.editorconfig` 的 `dotnet_diagnostic.*.severity` 与 csproj 属性 > 本文 > Microsoft Coding Conventions 原文 > Framework Design Guidelines（后者只管公共 API 的形状，不管排版）。
- 官方示例的"65 列"是文档站为移动端渲染设的，不能搬到产品代码；仓库未规定行长时按 120 列执行。
- runtime/compiler 的严格规则服务热路径性能，业务代码照抄会产出难读代码；冲突时以可读性优先，并给出理由。

## 2 缩进、行宽与排版

- 4 空格缩进，禁止制表符。理由：Visual Studio 默认与主流 `.editorconfig`（`indent_style = space`、`indent_size = 4`）一致，混用会让 diff 整块变色。
- 行宽：以仓库 `max_line_length` 为准，未配置时取 120；超长必须以更低的语法层级断行（参数之间、`&&` 之前）。
- 断行位置：在二元运算符**之前**断（官方 layout 约定），续行比当前语句多一个缩进（4 空格）。
- 大括号用 Allman：开括号独占一行，与声明同缩进；单语句 `if` 也加括号（IDE0011 `csharp_prefer_braces = true`），避免后续加行时漏掉作用域。
- 一行一条语句、一行一个声明；方法之间、属性之间至少一个空行。
- 复合条件加显式括号：`if ((startX > endX) && (startX > previousX))`，理由是不靠读者记忆运算符优先级。
- `using` 指令放在 namespace 声明**之外**：namespace 内的 using 会先按相对命名空间解析，新依赖引入同名段时旧代码会静默改变绑定（官方给了这个失败案例）。
- 不做横向对齐（`=`、`:`、行尾注释都不对齐）：重命名会让整块相关行变脏，评审噪声大于收益。

## 3 命名

| 对象 | 规则 | 示例 |
| --- | --- | --- |
| 命名空间 | PascalCase，反向域名 | `Contoso.Ordering.Infrastructure` |
| 类型（class/struct/record/enum/delegate） | PascalCase | `OrderService`、`ValueCoordinate` |
| 接口 | `I` + PascalCase | `IWorkerQueue` |
| 特性类 | PascalCase + `Attribute` 后缀 | `JsonIgnoreAttribute` |
| 方法、属性、事件、公开字段 | PascalCase | `ComputeTotal()`、`MaxRetries` |
| 常量（含 private const、局部 const） | PascalCase | `const int DefaultPort = 8080` |
| 局部变量、形参 | camelCase | `itemCount`、`someNumber` |
| private/internal 非 const 实例字段 | `_` + camelCase | `_workerQueue` |
| private/internal static 字段 | `s_` + camelCase | `s_workerQueue` |
| `[ThreadStatic]` static 字段 | `t_` + camelCase | `t_timeSpan` |
| 类型参数 | `T` 前缀的描述名；单参数可用 `T` | `TSession`、`T` |
| 枚举类型 | 非 flags 用单数名词，flags 用复数 | `Status`、`[Flags] Permissions` |
| 主构造函数参数（class/struct） | camelCase | `class DataService(IWorkerQueue workerQueue)` |
| 主构造函数参数（record） | PascalCase（会成为公开属性） | `record Person(string FirstName)` |

- 禁止连续两个下划线：`__` 形态留给编译器生成的名字，自己也用会与生成代码撞名。
- 不用单字母名，循环计数器除外；语言规范示例里的 `S`/`C`/`M`/`v`/`p`/`r` 只属于语法演示。
- 布尔成员用 `Is`/`Has`/`Can`/`Should` 前缀（`IsValid`）；异步方法加 `Async` 后缀（`LoadAsync`），命名规则可由 IDE1006 强制。
- 缩写按单词处理（`HtmlParser`，不是 `HTMLParser`）；公认缩写（Id、Url、Http）保持既有大小写，全仓库统一。

## 4 文件与模块组织

- 一个文件一个公开顶层类型，文件名 = 类型名；私有辅助类型可同文件，放在公开类型之后。
- 成员顺序：常量 → 字段 → 构造函数 → 属性 → 事件 → 方法。重载相邻；`Dispose(bool)` 紧跟构造函数，便于对照释放的资源。
- 命名空间用 file-scoped（`namespace Contoso.Ordering;`），IDE0161 的 `csharp_style_namespace_declarations = file_scoped` 可强制；一个文件只声明一个命名空间。
- 目录层级与命名空间一致（IDE0130 `dotnet_style_namespace_match_folder = true`），否则编辑器跳转和 analyzer 定位都要靠人脑补。
- 可见性显式写出（`dotnet_style_require_accessibility_modifiers = for_non_interface_members`），不依赖默认 `private`；公开 API 面越小越好。
- 跨项目共享的编译属性放 `Directory.Build.props`（`<Nullable>`、`<AnalysisLevel>`、`<LangVersion>`），单项目只留差异，避免几十份 csproj 各自漂移。

## 5 类型、值与不可变性

- `<Nullable>enable</Nullable>` 全仓库开启：引用类型默认不可空，可空必须写 `T?`。这是编译期契约，运行时行为不变。
- 可空意图三件套配合使用：注解（`string?`）、null-state 流分析（`if (x is not null)` 之后自动判为 not-null）、契约特性（`[NotNullWhen(true)]`、`[MaybeNullWhen(false)]`）。
- `!`（null-forgiving）只在流分析确实追不到的地方用一次，并在同一行或上一行注释说明为什么安全；每用一次就是关掉一处编译器的保护。
- 值语义/不可变数据用 `record` 或 `record struct`；需要身份、生命周期、可变状态用 `class`；DTO 用 `{ get; init; }` 或位置记录。
- 强制初始化用 `required` 成员，而不是"全参数构造函数 + 一堆 `ArgumentNullException`"；调用方在编译期就被拦住。
- 对外暴露只读集合：`IReadOnlyList<T>`、`IReadOnlyDictionary<K, V>`、`ReadOnlyMemory<T>`；不返回内部 `List<T>` 字段本身，否则封装随时被改穿。
- 集合初始化用集合表达式（`string[] vowels = ["a", "e", "i", "o", "u"];`），比 `new[] { ... }` 与 `new List<T> { ... }` 统一。
- 类型名用语言关键字：`string`/`int`/`object`，不写 `String`/`Int32`；一般算术用 `int` 而不用无符号类型，跨库交互代价更低（官方明示）。
- struct 的两个隐形陷阱：`default(Student)` 与 `new string[3]` 会让不可空引用字段实际为 `null`，而编译器不报警；用参数化构造函数、`required` 或集合表达式逐个填满。

## 6 函数与 API 设计

- 单表达式成员用表达式体（`=>`，IDE0022/IDE0025 可强制）；多语句、多分支用块体，不要在表达式体里塞三元嵌套。
- 参数顺序：必填输入在前，可选项在后；同类基本类型相邻（两个 `string`、两个 `bool`）时改用命名实参或 options record，避免调用点变成"位置猜谜"。
- 委托类型用 `Func<>`/`Action<>`，不自定义 delegate 类型；只在需要 `ref`/`out` 修饰或 `params` 语义时才定义具名 delegate。
- `var` 只在右侧类型一目了然时用（`new`、字面量、显式转换）；`foreach` 的循环变量写显式类型；LINQ 查询变量与匿名类型投影用 `var`。
- 静态成员用声明它的类型名访问（`ClassName.StaticMember`），不要用派生类名限定：编译能过，但读者会误判归属，新增同名声明的成员时还会崩。
- 不用 `null` 表示"查不到"：优先 `bool TryX(..., out T value)`、`T?` + `[NotNullWhen]`、或返回 `Optional<T>` 风格的领域类型，让缺失在签名上可见。
- 公共 API 的破坏性变更按 Framework Design Guidelines 处理：不删已发布成员、不改参数名（ApiCompat 可校验）、新增用重载或可选参数。
- 抛什么异常写进 `<exception>`，返回什么写进 `<returns>`；公共 API 的文档注释缺失当缺陷处理，不作装饰项。

## 7 错误处理

- 只捕获能处理的异常；捕获 `Exception` 必须带 `when` 过滤或立即 `throw;`，否则等于把未知故障降级成静默继续。
- 重抛用 `throw;`，不用 `throw ex;`：后者丢原始堆栈（CA2200 会报），排障时只能看到重抛点。
- 参数校验用 `ArgumentNullException.ThrowIfNull(x)` 与 `ArgumentOutOfRangeException.ThrowIfNegative(n)`；异常类型与失败原因对应，不要一律 `Exception`。
- 不用异常做常规控制流：解析失败用 `TryParse`/`TryGetValue`；异常只用于不满足前提的故障。
- `finally` 只留给无法 `using` 的清理（状态回滚、临时文件删除）；`using` 声明能表达的清理不要手写 try-finally。
- 需要降级的 catch 里写日志并明确返回什么（缓存未命中、默认配置），不写空 catch `{}`。
- 自定义异常继承最贴近的基类（`InvalidOperationException`/`ArgumentException`/`IOException`），并保留接受 `inner` 的构造函数。

## 8 并发、资源与生命周期

- 异步一路到底：禁止 `.Result`、`.Wait()`、`.GetAwaiter().GetResult()`。它们在线程池或带同步上下文的 UI 环境里会死锁，且把异步收益全部吃掉。
- 库与基础组件加 `ConfigureAwait(false)`；应用入口（UI、ASP.NET Core 请求管线）保持默认，否则上下文回不去。
- 返回 `Task`/`ValueTask`/`IAsyncEnumerable<T>`；`async void` 只允许事件处理器，其他位置异常无法被等待方观察到。
- 长耗时公共异步 API 必带 `CancellationToken` 参数并透传到最内层；中途丢 token 会让取消请求失效。
- 同步临界区用 `lock`（较新版本可用 `System.Threading.Lock`，IDE0330 会提示）；不要在 `lock` 内 `await`，也不要靠 `volatile` 拼可见性，复合操作必须有锁或原子类型。
- 共享字典用 `ConcurrentDictionary<K,V>`，读多写少的配置快照用 `ImmutableArray<T>`/`ImmutableDictionary<K,V>`；自己用 `lock` 包的 `Dictionary` 只在临界区极小且可控时接受。
- `IDisposable` 用 `using` 声明，`IAsyncDisposable` 用 `await using`；自己实现时走完整 Dispose 模式（`Dispose(bool)` + `GC.SuppressFinalize`），不要只写一个裸 `Dispose()`。
- 不用 `Task.Run` 把同步 CPU 代码"包成异步"；它只解决"别阻塞 UI 线程"，不增加吞吐，反而多一次调度开销。

## 9 注释与文档

- 单行注释用 `//`；注释独占一行（不写在代码行尾），`//` 后一个空格，首字母大写，结尾句号（官方 comment style）。
- 大段解释不要用 `/* */` 堆进代码：写在 PR 描述、设计文档或 `<remarks>` 里，代码块里只留与局部决策相关的一两句。
- 公共成员写 XML 文档：`<summary>`、`<param>`、`<typeparam>`、`<returns>`、`<exception>`、`<remarks>`，交叉引用用 `<see cref="..."/>` 与 `<seealso>`。
- csproj 开 `<GenerateDocumentationFile>true</GenerateDocumentationFile>`：让缺失或错位的 XML 注释在 `dotnet build` 暴露，而不是等着发布文档时才炸。
- 注释写"为什么"：为什么这里需要 `lock`、为什么这个分支不能删、为什么这里必须 `!`。不要复述类型和签名——那些由编译器与 IDE 提示提供。

## 10 工具链与验证

- `.editorconfig` 是唯一真理源：`indent_size`、`max_line_length`、`csharp_style_*`、`dotnet_style_*`、以及逐条的 `dotnet_diagnostic.IDE0011.severity = warning`。
- 把格式化本身当规则：`dotnet_diagnostic.IDE0055.severity = warning`，CI 跑 `dotnet format --verify-no-changes`，否则"格式已统一"只是口头约定。
- csproj 打开分析：`<AnalysisLevel>latest-recommended</AnalysisLevel>`（或 `latest`）选规则集，`<AnalysisMode>Recommended</AnalysisMode>` 起步、成熟后转 `All`，`<EnforceCodeStyleInBuild>true</EnforceCodeStyleInBuild>` 让 IDE 规则在 `dotnet build` 也生效（默认只在 IDE 里报）。
- `<TreatWarningsAsErrors>true</TreatWarningsAsErrors>` 配合 `<WarningsNotAsErrors>` 白名单；不这样做，警告在 CI 日志里沉底，几周后无人清理。
- 本地命令：`dotnet format`（改）、`dotnet format --verify-no-changes`（只检查）、`dotnet format style --severity warn`、`dotnet build -warnaserror`、`dotnet test`。
- 抑制规则要收敛：`#pragma warning disable` 只包住真正必须的那几行，并写理由；整文件级抑制等同删除检查。
- 生成代码显式排除：`.editorconfig` 里给 `[**/obj/**, **/*.Designer.cs] generated_code = true`，避免工具对不可手改的文件报错。

## 11 反例（Good / Bad）

```csharp
// Bad：用 null 表示"没有"，再用 ! 强行压掉编译器警告
public string LookupName(string id) =>
    _names.TryGetValue(id, out var name) ? name : null!;

// Good：缺失写进签名，调用方必须处理
public string? LookupNameOrNull(string id) =>
    _names.TryGetValue(id, out var name) ? name : null;
```

```csharp
// Bad：! 掩盖流分析，缺数据时在运行时抛 NullReferenceException
var order = _orders.FirstOrDefault(o => o.Id == id)!;
Console.WriteLine(order.Total);

// Good：把缺失做成显式分支，异常类型与信息都可定位
var order = _orders.FirstOrDefault(o => o.Id == id);
if (order is null)
{
    throw new KeyNotFoundException($"order {id} not found");
}

Console.WriteLine(order.Total);
```

```csharp
// Bad：同步阻塞异步；async void 让异常无人接管
public void Save()
{
    _repository.SaveAsync(_order).Wait();
}

public async void Refresh()
{
    await _repository.ReloadAsync();
}

// Good：全程异步并透传取消令牌，事件处理器之外不出现 async void
public async Task SaveAsync(CancellationToken cancellationToken) =>
    await _repository.SaveAsync(_order, cancellationToken);

public async Task RefreshAsync(CancellationToken cancellationToken) =>
    await _repository.ReloadAsync(cancellationToken);
```

```csharp
// Bad：空 catch 吞掉全部异常，手工 Dispose 漏掉异常路径之外的一致性
public void Write(string path, byte[] data)
{
    var stream = File.Create(path);
    try
    {
        stream.Write(data);
        Publish(path);
    }
    catch (Exception)
    {
    }
    finally
    {
        stream.Dispose();
    }
}

// Good：using 声明保证释放，只捕获能处理的异常并补上上下文
public void WriteSafely(string path, byte[] data)
{
    using var stream = File.Create(path);
    stream.Write(data);

    try
    {
        Publish(path);
    }
    catch (IOException ex)
    {
        throw new InvalidOperationException($"publish failed for {path}", ex);
    }
}
```

## 12 评审清单

- [ ] 新文件使用 file-scoped namespace，目录路径与命名空间一致。
- [ ] 引用类型可空性写全（`T?`），`!` 的每一处都有注释说明为什么安全。
- [ ] 没有 `.Result`/`.Wait()`/`GetAwaiter().GetResult()`，`async void` 只出现在事件处理器。
- [ ] 长耗时异步 API 接受并透传 `CancellationToken`。
- [ ] `catch` 要么处理，要么 `throw;`，没有 `catch (Exception) {}`。
- [ ] `IDisposable`/`IAsyncDisposable` 由 `using`/`await using` 释放，没有手写 try-finally 版 Dispose。
- [ ] 命名符合第 3 节表格（字段 `_`/`s_`/`t_` 前缀、接口 `I` 前缀、常量 PascalCase）。
- [ ] 对外暴露的是只读集合接口，不是内部可变集合。
- [ ] 公共成员有完整 XML 文档（`<summary>`/`<param>`/`<returns>`/`<exception>`）。
- [ ] `dotnet format --verify-no-changes` 与 `dotnet build -warnaserror` 在本地和 CI 都通过。
- [ ] 无新增 `#pragma warning disable`；确有必要时写了理由且作用域最小。
- [ ] 没有为了"看起来现代"引入未使用的语言特性（primary constructor、collection expression 等按需用）。

> 冲突时的裁决顺序：仓库 `.editorconfig` + analyzer/MSBuild 配置 > 本文 > Microsoft C# Coding Conventions 原文 > Framework Design Guidelines（仅公共 API 设计时适用）。
